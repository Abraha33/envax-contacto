# Phase 3 — Customer Catalog UI

## Objective
Implement the approved customer-facing catalog experience on top of the Phase 2 catalog API.

Planned branch: `build/catalog-ui-v1`

Entry conditions:
- `CATALOG DATA PASS`;
- `DESIGN READY` for the screens being implemented.

## In scope
- landing handoff into the app;
- catalog cover/index;
- browse by category and brand;
- category, brand, family, product and variant views;
- search and filters;
- responsive desktop/tablet/mobile behavior;
- loading, empty, error and 404 states;
- accessibility baseline;
- performance measurement.

## Out of scope
- favorites persistence;
- anonymous identity;
- pedidos;
- portal;
- promotions.

## Required outputs
A production-quality catalog experience that feels like a B2B digital catalog, not ecommerce, and uses only approved visual design.

## Exit
Phase 3 ends at `CATALOG UX PASS`.
